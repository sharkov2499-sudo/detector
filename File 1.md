There are 7 test cases in the testbench:
	1. Core functionality — verification of the basic detection logic for the full sequence (1101101). This test confirms that detector_out is activated only upon receiving the final bit and operates correctly under standard conditions.
	2. Overlapping — testing the FSM's ability to detect overlapping sequences. The test provides an input string where the trailing bit of the first occurrence serves as the starting bit for the next. In the golden module, this is achieved by transitioning to intermediate states (such as S2 or S5) instead of resetting to S0.
	3. EN control (S5 Pause) — verification of the enable signal functionality. The test advances the FSM to state S5 (11011), then deasserts en=0 for several clock cycles. It verifies that the FSM "freezes" its current state and ignores any input data until en returns to 1.
	4. Async/Sync Reset — testing the reset mechanism. The test asserts the rst signal mid-cycle (asynchronously) or at the clock edge when the output is high. It verifies the immediate clearing of the output and the return of the logic to the initial state S0.
	5. Long Complex Sequence — a stress test using a long input string with "false paths" (e.g., 11010...) and multiple overlaps. This verifies the stability of the transition logic in conditions where input data frequently mimics the start of the target sequence but fails to complete it.
	6. False Start Protection — testing protection against false positives. A continuous series of ones (1111111) is fed to the input. The test confirms that the FSM does not trigger the output, as the sequence lacks the necessary zeros in the required positions.
	7. EN at Final Bit — a specific verification of the en signal. The test deasserts en precisely at the moment the final bit of the sequence arrives. It verifies that the output 1 does not appear until en becomes high, confirming that the enable signal has full control over the output logic.
